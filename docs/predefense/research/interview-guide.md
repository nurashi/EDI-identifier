# User interview protocol

## Purpose and participants

Validate how freight EDI practitioners compare partner implementation guides and which requirements matter for the proposed toolkit. Target 3-5 representatives: integration engineers, logistics IT analysts, carrier/shipper interface owners or implementation consultants. A substantive client agreement can provide the alternative evidence specified by the pre-defense requirements.

## Consent and recording

Obtain permission to take notes and use anonymized findings. Record the date, relevant role, consent and a participant code. Keep contact information and confidential source material outside the public repository. Use non-confidential examples rather than production shipment or customer data.

## Questions

1. Describe the last time you needed to understand or compare a partner's EDI requirements. Which transaction and version were involved?
2. What inputs and tools did you use? Which steps required manual checking?
3. Which differences were difficult to interpret? Can you describe a non-confidential example?
4. How did you distinguish a missing rule from conflicting requirements?
5. How was a requirement decision checked or approved? What evidence was retained?
6. What would a comparison result need to show before you could trust it?
7. Which restrictions or concerns would affect adoption: data access, revisions, accuracy, integration or workflow?
8. Looking at the prototype, which action would you take first and what is unclear?

Ask for examples and distinguish recalled estimates from measured timings. Avoid introducing a benefit before the participant describes their experience.

## Analysis record

Record the participant code and role, discussion date, workflow example, observation, interpretation, contradictory feedback, affected requirement and proposed change. Preserve a reference to the underlying notes in the restricted research records.

Summarize findings by theme, including negative feedback. Map each finding to a requirement, architectural decision or scope change. Keep observations from different participants separate and retain the rationale for each resulting change.
